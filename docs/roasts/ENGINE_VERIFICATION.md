## Requirements exercised

- **Truthful input:** missing values remain unknown; missing DTO values do not become zero. Precipitation probability does not imply observed rain or intensity. OpenWeather 511, 520, 781, smoke, ash and squall retain their documented meaning. AQI requires its explicit provider scale. Metric/imperial conversion occurs once. Current evaluation time is separate from observation time.
- **Place and interval:** selected-place identity must match bundle metadata. Local date/daypart uses the selected place's IANA time zone, including spring DST gaps, autumn overlaps and midnight. Hourly, commute and weekend contexts require actual coverage of their requested intervals. Friday's current weather does not become weekend weather. Hazardous periods within a forecast window remain safety-relevant even when aggregate weather is pleasant.
- **Hard eligibility:** required-all, grouped any-of, forbidden, numeric units, scope, age, valid dates, status, region, locale, placeholders and intensity stay mandatory. An unknown forbidden fact cannot establish a negative claim. Neither exhausted history nor high weight bypasses a constraint. Stale numeric-only/any-of rules reject factual copy. Application-owned safety and context-free fallback work without a loaded pack.
- **Safety handoff:** current hazards block humor even without an invented official alert. Positive rules carry immutable `requiresVerifiedAlerts` metadata into saved selections, including rules whose line tags contain no `nice` tag. Missing/unknown alert coverage blocks that historical positive selection; context-free copy remains usable. Direct tests cover 781, 511, null weather and legacy positive tags.
- **Stable display:** seeded selection is independent of catalog iteration order and Dart's runtime hash. Rebuilds reuse an eligible selection. Refreshed observation provenance and rendered units update without claiming another exposure. New selections are recorded only through explicit display commit. History caps are 200 IDs and 50 families per persona, 200 exact displayed selections total, and 100 cached slots. Persisted schema migration retains available historical captions while dropping old coordinate-bearing slot keys.
- **Identity and privacy:** persona aliases normalize to the existing canonical identities; all ten moods map to the existing same-persona expression assets. Selection slot keys hash the transient place identity with SHA-256. Tests check that serialized history contains no raw coordinate key. Roast diagnostics expose scope/time/freshness/fact provenance without coordinates, caption text or user identifiers. The local exposure record intentionally preserves the displayed caption for later handoff; it is not uploaded as telemetry.
- **Local favorites and feedback:** controller APIs expose favorite IDs and liked/disliked/cleared opinions without adding UI. Each store retains at most 200 IDs in local preferences. Favorites multiply chance by 1.5, likes by 2 and dislikes by 0.5 only within the already eligible/relevant/repetition-filtered pool; the selector bounds incoming multipliers. Tests cover restart/removal, bounded storage, immutable public views, invalid IDs, stable displayed selection, deterministic row-order independence and inability to override facts, intensity, recalls or safety. Dislikes remain a soft preference rather than removing the last truthful option.
- **No selection traffic:** the shared controller receives existing weather state. Selection, rebuilds, persona changes and display commits do not refresh weather, call AI or invoke optional content sync. Repeated bundle loads do not issue update requests. Optional updates default to disabled.
- **Optional update bounds:** explicit foreground scheduling, at least seven elapsed days between attempts, jitter, bounded failure backoff, per-instance in-flight deduplication, persisted reservation before traffic and a rolling 30-day budget are exercised. Defaults are a 4 KiB manifest, 256 KiB transfer, 2 MiB decoded pack and 1 MiB optional traffic allowance, with a fixed 1 KiB allowance per response. Failed transfers retain their full reservation. Disallowed origins, insecure URLs, redirects, incompatible schema/builds, unknown fields, oversized data, hash mismatches and malformed content retain working local content.
- **Update continuity:** relevant persona/locale shards are verified and atomically installed. A newly advertised version cannot invalidate an older working local pack. A legacy subset pack cannot erase other bundled personas or reinterpret their rules. Active/previous versions support corruption recovery and rollback. Persisted disabled IDs apply to bundled content as well; the manifest download kill switch still carries recalls.
- **Durable storage isolation:** native files and IndexedDB store content-addressed blobs and a small active/previous pointer. Large JSON packs do not enter preferences. Blobs occupy `metadata/roast_blob_<sha256>`; they do not share the saved meme document namespace. Regression tests verify clean `MemeStore.listDocuments`, unchanged library metadata, successful media collection, and migration of verified early roast blobs out of `documents`. Interrupted writes, concurrent writes within one cache instance, warm restart, corruption and eviction are exercised.

Provider semantics were checked against the official [OpenWeather condition codes](https://openweathermap.org/api/weather-conditions), [current-weather units](https://openweathermap.org/api/current) and [Air Pollution API scale](https://openweathermap.org/api/air-pollution). The adapter does not infer US AQI from OpenWeather's 1–5 scale.

## Weather boundary review

`CacheService` uses exact latitude/longitude weather keys. It reads an older rounded key only when the cached payload proves the exact requested coordinates; unrelated settings and old entries are retained. Corrupt exact-cache JSON returns a cache miss instead of preventing refresh. This weather cache intentionally retains weather coordinates; the humor history and diagnostics do not add raw coordinates.

`OpenWeatherRepository` and `OpenWeatherBackendClient` deduplicate identical in-flight requests with exact place/endpoint parameters. Nearby coordinates remain separate. Backend DTOs carry known-value flags and explicit AQI source/scale into the local adapter. Client diagnostic counters distinguish backend HTTP requests and bytes from provider requests. Failure logging records status/type/byte counts rather than raw response bodies or exception strings that can include coordinate query strings.

The reviewed Functions source preserves exact endpoint, coordinate, unit and route parameters in provider cache keys. Process-local successful response caching, in-flight reuse and bounded recent-failure caching reduce duplicate traffic without merging locations. HTTP 429 is not retried; existing bounded 5xx retry behavior remains. Provider counters increment at actual upstream fetch attempts, including retry attempts, rather than inferring provider use from client requests. These source changes have not been deployed or compared against live provider billing in this task. Process-local counters/cache are not a distributed service-wide total or cache.

## Transport evidence and remaining limits

The native gzip test uses a real local `HttpServer` and Dart's `IOClient`, not a mocked downloader. It serves a gzip-encoded response, verifies the resulting JSON bytes/hash after exactly one HTTP decode, checks compressed-length accounting and rejects a decoded payload over its bound. Header rejection is separately tested to abort the request and cancel an unread response stream. A separate pending async-read fixture confirms that timeout abort happens before awaiting stream cancellation and that the same downloader can handle a later request. This establishes native local-stack behavior only.

Chrome executes the real browser transport and real IndexedDB. The transport test substitutes `fetch` with a browser `Response` fixture and inspects `credentials: omit`, `redirect: error`, method, streamed bytes and request cancellation. Omitting credentials also covers same-origin cookies, which the default `BrowserClient` setting would otherwise permit. A second browser transport test uses an actual `ReadableStream` that stalls until its request abort signal fires. It confirms bounded timeout completion without a second unhandled abort error, then advances the scheduler clock and completes a later sync through the same downloader/scheduler. Production now aborts inside the stream timeout callback before emitting the timeout; abort-related browser read rejection is consumed during cancellation. The default header/body-idle timeout remains 15 seconds. The IndexedDB test opens a fresh database, creates a new cache/repository instance, proves warm loading without another bundled-asset load and exercises eviction recovery. The fetch fixture does **not** prove deployed CORS, CDN headers or browser gzip/Brotli behavior.

No static Hosting origin/target has been verified or published. Optional updates must stay disabled until the intended existing site, allowlisted origin, manifest and immutable paths, HTTPS, MIME type, CORS, cache headers and native/browser compression are verified. Hashes cover exact decoded UTF-8 JSON bytes, not gzip sidecar bytes. Without a trustworthy visible compressed Content-Length, the downloader conservatively bounds/account estimates using decoded bytes. Header overhead is an allowance, not an exact measurement of TLS/HTTP wire traffic.

The persisted budget and scheduler govern the normal shared application instance. Preferences are not a cross-tab/process atomic lock: simultaneous independent browser tabs, clearing storage, private browsing or browser eviction can reset or race the local allowance. It is a conservative device mechanism, not a global billing cap. A verified deployment still needs server/provider budget monitoring and a rollback/kill-switch procedure. Offline clients cannot receive a new recall until their next permitted sync.

The adapter supports interval contexts for future use, but the approved UI has no additional hourly/daily roast slots or new activity/feedback controls. None were added. Activity/intensity and favorites/feedback remain local model capabilities; the controller exposes explicit setters for future approved UI wiring. Rain start time, long-term personal weather history, precise seasonal/calendar claims and other unavailable facts stay unknown; the implementation does not fetch extra data to unlock copy. Editorial content is currently en-US, and unsupported locales use application-owned fallback. New prose remains machine-reviewed, not claimed as human-approved.
